Where should the Scale Station app live?

This is the most foundational decision — it affects deployment, auth, and how the two apps share data.

A

Inside the existing Renovo Pro project

New route prefix /scale/* for the tablet app and /scale/admin/* for the admin portal — all in the same Next.js codebase.

Pros

  • Shares database, models, products & customers instantly
  • One deployment (Vercel) — no second hosting cost
  • Reuses existing auth, R2 upload, PDF/print code
  • No data sync needed between two apps

Cons

  • Tablet operators share the same login system (can be worked around with a PIN/kiosk role)
  • Slightly more complex route structure
B

Completely separate Next.js app

A brand-new repo/project deployed independently, connecting to the same PostgreSQL database.

Pros

  • Total isolation — can be deployed on a local device or intranet
  • Custom, minimal UI without legacy complexity

Cons

  • Second database connection / second Vercel project
  • Must duplicate or package shared code (schemas, services)
  • Two places to manage migrations, products, customers
  • More ongoing maintenance

💡 My recommendation: Option A — building inside the existing project is far simpler and leverages everything already built (customers, products, R2 uploads, PDF slips). The tablet app just gets its own clean routes and a kiosk-style PIN login.
