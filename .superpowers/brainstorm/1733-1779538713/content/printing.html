How should the order slip be printed?

The slip shows: customer name, product, weight, and order number (no price). What printer setup does the scale station use?

A

Thermal receipt printer (ESC/POS)

Uses the existing node-thermal-printer library already in the project. Connects via USB or network. Prints an 80mm roll slip instantly.

Pros

  • Fast, professional, paper-saving
  • Already supported in the codebase (src/lib/print/thermal.ts)
  • Typical for scale/weigh-bridge environments

Cons

  • Requires a thermal printer physically at the scale
  • Server-side print call — tablet sends request to API
B

PDF slip — browser print dialog

Generates a PDF using the existing generateTransactionSlip (pdf-lib, 80mm style). Opens browser print dialog — works with any printer including network printers.

Pros

  • Works with any printer — no special hardware required
  • PDF is saved to R2 for records
  • Already supported in the codebase (src/lib/pdf/slip.ts)

Cons

  • Browser print dialog adds an extra tap on tablet
  • Slightly slower than direct thermal print
C

Both — thermal if available, PDF fallback

Try thermal printer first; if unavailable or not configured, fall back to PDF browser print.

Pros

  • Maximum flexibility
  • Works in all environments

Cons

  • More complex to implement and configure

💡 My recommendation: Option B — PDF slip with browser print. It saves every slip to R2 automatically (audit trail), works with any printer on the network, and reuses code already in the project. Thermal can always be added later.
